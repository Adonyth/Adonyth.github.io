## 1. 设计原则

1. **零交易**：协议全程不发生、不模拟、不暗示任何交易动作。没有仓位概念，
   没有 P&L 概念，没有"如果当时买了"的回算。
2. **预登记**：每日预测必须在当日市场开盘前 commit 进 git（commit 时间戳即登记证明）。
   开盘后提交的预测标记 `late=true`，参与记录但单独统计。
3. **分布而非方向**：预测对象是次日收益的**完整概率分布**，不是涨/跌方向。
   方向预测天然带有行动暗示；分布校准才是本项目要演示的能力。
4. **评分规则 proper**：只用 proper scoring rules（CRPS 等），
   使"如实报告自己的真实信念"成为唯一最优策略。
5. **可复现**：评分代码开源，输入数据来源公开，任何人可重算每一行分数。

## 2. Universe（预测标的范围）

固定 10 个高流动性、公开数据极易获得的标的，sprint 期间不增减：

| 组 | 标的 | 理由 |
|---|---|---|
| 宽基指数 ETF | SPY, QQQ, IWM | 数据干净，无个股新闻噪声主导 |
| 行业/资产 ETF | XLE, GLD, TLT | 引入不同波动 regime |
| 大盘个股 | AAPL, MSFT | 测试个股层面的校准（更难） |
| 汇率 | EURUSD | 非股票资产类 |
| 波动率指数 | VIX（水平值，非收益） | 测试对非价格量的分布校准 |

选择标准只有一个：**结果数据公开、无歧义、T+0 可获得**。
与"看好哪个"完全无关——universe 是评分练习的题目集，不是观点表达。

## 3. 每日预测格式

每个标的预测**次日收盘对今日收盘的对数收益**（VIX 为次日收盘水平值）的分布，
用 5 个分位数表示：

```
quantiles: [q05, q25, q50, q75, q95]
```

- 5 分位数足以算 CRPS 近似、PIT 分桶和两档区间 coverage（90% 与 50%）。
- 必须单调递增，violation 直接拒绝录入。
- 每个预测附带 `method` 字段（见第 4 节的预测源）。

## 4. 预测源与 baselines

每天每个标的，记录 3–4 条预测（每条独立评分）：

| 源 ID | 描述 | 角色 |
|---|---|---|
| `B0-flat` | 无信息 baseline：q50=0，分位距取过去 60 个交易日收益的经验分位数 | 必须战胜的底线 |
| `B1-garch` | GARCH(1,1)（或 EWMA 波动率）拟合的正态分布分位数 | 标准统计 baseline |
| `M1-llm` | 让一个 LLM（建议 Codex/Ollama 跑，省 Fable 5 额度）基于公开信息给分位数 | 被审计对象示例 |
| `H1-human`（可选） | 你自己手填的分位数 | 自我校准练习 |

**关键点**：本项目的"成果"不是某个源赢了——而是**这套评分流程本身跑通且公开**。
即使所有源都不如 B0，账本照样成立（它如实记录了这一点，这正是审计层的工作）。

## 5. Scoring metrics

每个 resolved 预测计算：

1. **CRPS**（pinball-loss 近似）：对 5 个分位数 τ∈{.05,.25,.50,.75,.95} 求
   quantile loss 的平均：`QL_τ = (𝟙[y<q_τ] − τ)·(q_τ − y)`。值越小越好。
   报告时除以 B0 的 CRPS 得 skill score（<1 即优于无信息基线）。
2. **PIT**：实现值落入哪个分位段（<q05, q05–q25, q25–q50, q50–q75, q75–q95, >q95）。
   校准良好时各段频率应接近 (.05,.20,.25,.25,.20,.05)。每 7 天画一次直方图。
3. **Coverage**：90% 区间（q05–q95）和 50% 区间（q25–q75）的实际覆盖率。
   目标 90%±经验误差、50%±经验误差；12 天样本极小，只看方向不下结论。
4. **Conditional coverage**：按前一日波动状态（VIX 高于/低于其 20 日中位数）分桶
   的 coverage——检查"是不是只在平静日校准"。12 天内仅记录，不判定。

**样本量诚实条款**：12 天 × 10 标的 ≈ 120 行/源。这足以演示流程、
发现严重失准，**不足以**支持任何"校准良好"的正面 claim。
12 天结束时允许的最强说法："流程已验证可运行，初步 PIT/coverage 见报告，
统计结论需 ≥60 个交易日。"

## 6. Ledger schema

存储：专用私有 git repo（或 WMDB 子目录）`[VERIFY-LOCAL: 按 REPO_PUBLIC_SPLIT 决定公开时点]`，
每天两个文件：

**forecasts/YYYY-MM-DD.jsonl**（开盘前 commit）：
```json
{"date":"2026-06-11","ticker":"SPY","target":"log_return_next_close",
 "source":"B1-garch","q05":-0.0142,"q25":-0.0051,"q50":0.0002,
 "q75":0.0055,"q95":0.0148,"created_utc":"2026-06-11T12:40:03Z",
 "late":false,"protocol_version":"1.0"}
```

**resolutions/YYYY-MM-DD.jsonl**（次日收盘后 commit）：
```json
{"date":"2026-06-11","ticker":"SPY","realized":0.0031,
 "data_source":"<公开行情源>","resolved_utc":"2026-06-12T21:05:11Z",
 "scores":{"crps":0.0041,"pit_bucket":"q50-q75",
 "in90":true,"in50":true}}
```

规则：
- 两类文件 append-only；修改历史行 = 协议违规，必须在 `AMENDMENTS.md` 留痕说明。
- git commit 时间戳是预登记证明；不要 rebase/squash 这个 repo。
- 不存任何账户、仓位、个人金融信息——schema 里没有这些字段，永远不加。

## 7. 12 天最小运行计划

| 日 | 动作 |
|---|---|
| D1（6/10） | repo 初始化、本协议 commit（即协议本身的预登记）、脚本 spec 交给 Codex、当晚生成首日预测 |
| D2–D5 | 每日仪式（生成→commit→次日评分），脚本逐步替代手工 |
| D6（6/15） | 流程检查：仪式耗时是否 ≤30 分钟？没达到则修流程 |
| D9（6/18） | 首份 7 日滚动报告：PIT 直方图 + coverage 表 + skill scores |
| D12–13（6/21–22） | 12 天总报告 + 续跑决策（见第 8 节） |

注意：周末与节假日无市场数据，实际 resolved 行数约 8–9 个交易日 × 10 标的。

## 8. 续跑决策树（6/22 执行）

- 仪式平均耗时 ≤30 分钟 且 0 次断更 → **续跑 60 个交易日**（升 L3 证据的最短路径）。
- 断更 1–2 次 → 修流程（自动化更多环节）后续跑。
- 断更 ≥3 次或仪式 >45 分钟 → 流程设计失败，重新设计后再启动，不带病续跑。
- 任何情况下都**不**因"分数不好看"停跑——分数不好看恰恰是账本可信的证据。

## 9. No-trading / No-advice 硬边界

1. 本协议产出的任何数字不得用于实际交易决策；如果你本人要做任何个人投资操作，
   与本账本完全隔离（时间、工具、文档都隔离）。
2. 不开发任何下单、模拟盘、信号推送功能；收到此类功能请求一律拒绝并引用本节。
3. 不保存、不请求任何券商凭证。
4. 对外发布只发：方法论、汇总校准报告（≥7 天聚合）、代码。
   **不发**：逐日预测明细的实时流（防止被当作信号源使用）。历史明细可在
   延迟 ≥5 个交易日后公开（保留可审计性，消除时效价值）。
5. 所有对外材料带英文免责声明（见文件头）。
6. LLM 预测源（M1）的 prompt 中明确告知模型这是校准研究，要求输出分位数而非观点。

## 11. 附录：交给 Codex 的脚本 spec（一次写清）

1. `make_forecast_template.py`：输入日期+universe → 拉取过去 60 交易日收盘价
   （公开数据源）→ 生成 B0/B1 分位数 → 输出当日 forecasts JSONL（M1/H1 行留空待填）。
2. `score_day.py`：输入日期 → 拉取实现值 → 校验单调性与时间戳 → 计算第 5 节

3. `report.py`：输入日期范围 → PIT 直方图（PNG）+ coverage/skill 表（Markdown）。
4. 全部脚本：无网络写操作、无凭证、纯只读公开数据；单元测试用合成数据。

# OMYTEA_LANDING_MASTER_PLAN — "落地"的可验证定义

> "落地" = 从"founder 给自己的预测评分"变成
> **"至少一个非 owner 的预测源持续流经 Omytea 的收据层，且至少一个外部人
> 因此改变了行为（使用/引用/付钱）"**。其余一切都是过程。

## 30 天目标（至 2026-07-10）

| # | 目标 | 验证方式 |
|---|---|---|
| 30-1 | 5 个 D1 目标用户访谈完成，pain 证实或证伪 | 访谈纪要 ≥5 份，含原话引用 |
| 30-2 | Receipt 公开页 v0 上线（哪怕手工生成） | 一个可分享 URL，外人 30 秒内看懂"这是什么" |
| 30-3 | 1 个 non-owner 预测源接入（concierge 方式，手工都行） | 该源 ≥10 行预登记记录入账 |
| 30-4 | Console 重构 P0 完成（CURSOR_UI_REFACTOR_TASKS P0 列） | 截图对比 + 一个陌生人的首次使用录屏无致命困惑 |
| 30-5 | Attorney 问题清单已发出且至少收到初步回复 | 邮件记录 |

## 60 天目标（至 2026-08-10）

- 3 个 non-owner 预测源在账（其中 ≥1 个是 AI agent 输出流）
- 第一次 resolution 周期跑完：外部源拿到自己的第一份校准报告
- 1 个 design partner 口头承诺（书面更好；金额可以是 0，承诺必须具体：
  每周接入数据 + 每两周反馈）
- 公开 landing 重写上线，按 claims matrix 全句过审
- Go/no-go 复核：D1 的 pain 若被 5+ 访谈证伪 → 启动 D2 优先的 plan B

## 90 天目标（至 2026-09-10）

- 第一笔收入或第一份付费意向书（金额不设目标，性质必须是"为收据/审计付费"）
- ≥100 行 non-owner resolved rows
- Omytea 自己的 finance ledger（若持续运行）作为公开 credibility artifact 发布
  （前提：attorney 意见允许）
- 决定：融资 / 继续 bootstrap / 方向调整——基于上述真实数据而非感觉

## 关键首次里程碑（按时间序）

1. **第一个可验证里程碑**：陌生人看 receipt 页 30 秒后能复述"这是预测的
   收据"（5 人测试 ≥3 人通过）——目标 D+10
2. **第一个 non-owner resolved row**：外部源的预测完成登记→resolution→评分
   全周期——目标 D+21（golf 路径若 GO 可能更早实现此里程碑）
3. **第一个公开 artifact**：receipt 页或重写后的 landing 任一公开——目标 D+14
4. **第一个 buyer discovery 里程碑**：第 5 个 D1 访谈完成且记录"愿意付钱吗"
   的真实回答——目标 D+14

## 不做什么（90 天内）

- 不做 D3/D5（research integrity、bank compliance）任何动作
- 不做自动交易相关任何字节；finance ledger 维持冻结边界
- 不做融资 roadshow（材料可以备，不主动跑）
- 不做多租户 SaaS 工程化（auth/billing/scale）——concierge 优先
- 不发明新评分理论；CRPS/PIT/coverage 够用
- 不做移动 app；响应式 web 够用

## Stop rules

- **访谈证伪线**：10 个 D1 访谈后无一人确认 pain 且无一人愿试用 →
  D1 降级，D2/D8 提升，写 pivot memo（不是失败，是审计在工作）
- **30 天里程碑全红** → 暂停产品工作，一周纯 discovery
- **任何对外材料越过 claims matrix** → 当日停传播（沿用全局 stop rule）
- **founder 连续 5 天无法投入 ≥2 小时** → 收缩 scope 到"每周一个访谈 +
  receipt 页维护"的最小存活模式，不假装在全速跑

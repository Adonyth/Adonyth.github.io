# AGENT_OPERATING_MANUAL — 多 agent 长期协作操作手册 v1.0

> 源文件状态：基于任务描述中列出的工具集（Fable 5 / Codex / Cursor /
> OpenClaw / scnet / Ollama / OpenSpace）构建。各工具的实际配额、版本、
> 环境细节标 `[VERIFY-LOCAL]`。本手册在 D6 和 D9 各修订一次（按实际用法）。

## 1. 路由总原则

**一个判断题决定路由：这个任务的瓶颈是"想清楚"还是"做出来"？**

- 瓶颈是想清楚（综合、判断、一致性、对抗审查）→ **Fable 5**
- 瓶颈是做出来且 spec 能一次写清 → **Codex**
- 瓶颈是做出来但 spec 要边做边发现 → **Cursor**（你在环路里）
- 瓶颈是重复操作 → **OpenClaw** / 脚本
- 瓶颈是算力 → **scnet**
- 瓶颈是隐私（数据不能出本机）→ **Ollama**
- 空间/3D 内容 → **OpenSpace** `[VERIFY-LOCAL: 实际用途]`

## 2. 分工明细表

### 给 Fable 5（长上下文 + 长程推理是它的相对优势，按优势计费思维使用）

| 任务类型 | 例子 |
|---|---|
| 跨文档综合与一致性审查 | "这 8 份文档里关于 golf 的说法有没有互相矛盾" |
| Claim 分级与对外材料审查 | 按 PUBLIC_CLAIMS_MATRIX 逐句审 pitch |
| 对抗性角色扮演 | 模拟最不客气的投资人/审稿人攻击你的叙事 |
| 实验判读（判官模式） | 按冻结阈值判 PASS/FAIL，写停止声明 |
| 高质量长文写作 | 文章初稿、决策备忘、复盘 |
| 决策框架构建 | go/no-go criteria 设计、决策树 |
| 多步骤自主任务 | 给一个目标 + 边界，自己规划执行（如本 sprint 包的生成） |

### 给 Codex

- spec 明确的脚本/函数实现（ledger 脚本、评分函数、数据抓取）
- 评测代码的独立审查（用与编写者不同的会话）
- 批量内容的格式转换、模板填充
- M1-llm 预测源的日常生成（省 Fable 5 额度）

### 给 Cursor

- 交互式调试、环境配置（试错型工作）
- 实验脚手架搭建（数据 split、harness——需要边跑边看）
- 小步重构、IDE 内的快速修改

### 给 OpenClaw / scnet / Ollama / OpenSpace

| 工具 | 用途 | 禁区 |
|---|---|---|
| OpenClaw | 浏览器自动化：数据源排查、表单类重复操作 | 不碰任何登录态下的金融/个人账户页面 |
| scnet | 批量实验 runs（V10/V2 gate）、长时间训练 | 固定 seed、结果落盘才算完成 `[VERIFY-LOCAL: 配额]` |
| Ollama | 涉及个人信息的本地文档整理；离线草稿；隐私敏感的预处理 | 输出质量要求高的对外材料不用它终稿 |
| OpenSpace | `[VERIFY-LOCAL]` | — |

## 3. 什么情况下不该用 Fable 5

1. **spec 已经一次写清的纯执行**——给 Codex，Fable 5 写boilerplate是浪费。
2. **试错型环境调试**——"为什么这个包装不上"类问题给 Cursor，
   Fable 5 的长程推理用在排错循环上性价比最差。
3. **需要保密的个人敏感数据处理**——用 Ollama 本地跑。
4. **你还没想清楚要什么的时候让它"随便看看"**——没有目标的探索会消耗大量
   额度产出泛泛综述。先用 10 分钟人工把问题收窄成一个可判定的问题。
5. **作为搜索引擎用**——事实查询用搜索，Fable 5 用来处理查回来的东西。
6. **让它替你做你必须自己做的决定**——它可以列证据、建框架、给推荐，
   但 DECISION 区的签字必须是你。

## 4. 任务委派模板

每次给任何 agent 派任务，五要素缺一不可：

```
【目标】一句话，可判定完成与否
【输入】明确的文件/数据/上下文（路径写全）
【边界】不许做什么（敏感文件、scope、claim 级别）
【产出】文件路径 + 格式
【验收】done criteria，最好可机器检查
```

**示例（派给 Codex）**：
> 【目标】实现 score_day.py，对指定日期的 forecasts 计算 CRPS/PIT/coverage
> 【输入】FINANCE_CALIBRATION_LEDGER_PROTOCOL.md 第 5、6、11 节
> 【边界】只读公开行情数据；不加任何 schema 外字段；无网络写操作
> 【产出】scripts/score_day.py + 合成数据单元测试
> 【验收】pytest 全绿；对协议文档中的示例 JSON 算出可手工复核的分数

## 5. Prompt 模板库（本 sprint 实测后沉淀，D9 定稿）

**P1 跨文档一致性审查（Fable 5）**
```
读取 [文件列表]。找出：(1) 互相矛盾的陈述；(2) 同一概念的不同命名；
(3) 与 PUBLIC_CLAIMS_MATRIX 冲突的 claim 级别。
只报告问题和位置，不要复述文档内容。按严重度排序。
```

**P2 对抗性 Q&A 演练（Fable 5）**
```
你扮演 [最挑剔的技术投资人 / 顶会审稿人 / 资深合规律师]。
读 [材料]。提出 10 个最难回答的问题，从最致命的开始。
我逐个口头作答后，你按 (a) 是否诚实 (b) 是否越级 claim
(c) 是否答非所问 三个维度打分并给出更好的答法。
```

**P3 对外材料 claim 审查（Fable 5，发布前强制）**
```
用 PUBLIC_CLAIMS_MATRIX.md 审查 [材料]。对每个含事实性声明的句子输出：
句子 | claim 级别 | 证据级别 | 判定（OK/降级改写/删除）。
特别检查第 3.3 节禁止清单和第 4、5 节的 quantum/prediction 措辞规范。
最后给出改写后的全文。
```

**P4 决策备忘生成（Fable 5）**
```
就 [决策问题] 写决策备忘：先写"这个决策真正在问什么"（往往和表面问题不同），
然后给出可检验的 go/no-go criteria（每条附检验方法和 PASS 标准），
最后留 DECISION 空白区由我填。禁止替我做最终判定。
```

**P5 实验判读·判官模式（Fable 5）**
```
你的任务是按 [gate 文档] 中冻结的阈值判定 label，
不是为结果寻找最有利的解释。读取 [结果文件]。
输出：观测值 vs 阈值的逐条对比、sanity checks 核对、
唯一 label（PASS/FAIL-*/KILLED）、若 FAIL 则附停止声明草稿。
如果你发现自己在写"虽然…但是…"，停下来，那是辩护不是判读。
```

**P6 日终复盘（Fable 5，轻量）**
```
今天是 sprint D[n]。对照 FABLE5_MASTER_PLAN.md 的当日 done criteria：
(1) 哪些达成/未达成（要证据，如 commit hash）；
(2) 未达成的，是计划问题还是执行问题；
(3) 明天上午的第一个任务是什么；
(4) 今天有没有任何对外表述越过 claims matrix。
输出 ≤15 行。
```

**P7 周复盘（Fable 5，每周日）**
```
读本周全部日复盘 + git log。回答：
(1) 五条轨道各自的真实进度 vs 计划（红/黄/绿）；
(2) 本周最大的一次时间错配（花了大时间的低价值事）；
(3) agent 分工哪里失灵（该给 Codex 的给了 Fable 5，或反之）；
(4) 下周要改的一条流程（只改一条，改多了等于没改）。
```

## 6. 复盘机制

- **每日（21:30，15 分钟）**：P6 模板。产出追加到 `daily_log.md`（本目录）。
- **每周（周日晚，45 分钟）**：P7 模板。产出 `WEEKLY_RETRO_[日期].md`。
- **Sprint 末（6/22）**：完整复盘 `RETRO_2026-06-22.md`，
  含 agent 分工效果评估——本手册的 v1.1 修订依据。
- **复盘的纪律**：复盘只产生 (a) 流程修改 (b) 下期任务，
  不产生自责和重新立志。连续两周同一问题出现 → 那是系统问题，改系统。

## 7. 额度与降级

- 每日复盘记录当日 Fable 5 会话数/大致消耗。
- 降级次序见 FABLE5_MASTER_PLAN 第 5 节。
- 经验法则：Fable 5 的每次调用应该要么 (a) 动用了 >3 个文档的上下文，
  要么 (b) 需要对抗性/判官级的推理质量，要么 (c) 产出直接对外。
  三者皆否 → 降级到 Codex/Cursor/Ollama。

# BETTER_THAN_CURRENT_PLAN — 怎么做得更有格局、更卓越

> 每条 = 现状 → 更好的版本 → 第一步行动。拒绝不落地的宏大。

## 1. 更大的问题定义

- **现状**：「AI 预测泛滥后，谁来记账」——对，但守势。
- **更好**：「预测正在成为一种经济（agent 决策、模型断言、专家观点都在
  被定价），而**每一种经济在规模化时都发明过自己的会计制度**——复式
  记账之于贸易资本主义、审计之于股份公司、信用评分之于消费信贷。
  预测经济的会计制度还没有被发明。我们在发明它。」
- 这个定义更大且更硬：它把 Omytea 从"信任工具"升格为"制度发明者"，
  同时每一步仍落在收据上。
- **第一步**：amendment §A 采纳（已草拟）。

## 2. 更强的 product wedge

- **现状**：D1 = agent 团队的校准收据（对）。
- **更好**：D1 + **"采购质询包"切入**——不卖"长期校准"（慢价值），
  卖"下周一客户尽调会上能甩出来的审计附件"（即时价值）。
  同一机制，销售对象从工程师改为"正在丢单的创始人"。
- **第一步**：FP-5 访谈脚本已含采购质询问题；one-pager CTA 措辞
  从 "get receipts" 调成 "pass your next vendor due-diligence"
  （CX-4 的 SUGGESTIONS 区处理，仍需 P3 审）。

## 3. 更硬的证据路线

- **现状**：访谈 + concierge（对，但单线程）。
- **更好**：三轨并行且互锁——①市场证据（5 访谈）②机制证据
  （finance ledger 60 天可选续跑）③**公开赌注证据（新）**：Omytea 把
  自己的关键商业假设也登记成收据（"30 天内 ≥1 个 agent 团队同意
  concierge audit——概率 X%"），公开、可被打脸。**用自己的机制赌
  自己的命运，是这个项目能做出的最硬的诚实演示。**
- **第一步**：发布前 3 张 "founder receipts"（设计已支持，零新代码）。

## 4. 更清晰的 technical moat

- **现状**："中立 + 数据累积"（对但软）。
- **更好**：四层阶梯明确写出——①server-side 时间戳（周级可达）
  ②开源独立 verifier（任何人可复算一切分数；"我们的秘密是没有秘密"）
  ③RFC3161/OpenTimestamps 第三方锚定（月级）④跨源 track record 图谱
  （年级，真正的网络效应）。每层都是可对外声称的具体资产，
  而不是一句"我们中立"。
- **第一步**：verifier 从 validate_ledger.py 泛化（CX 任务排入 v1）。

## 5. 更有力的 public narrative

- **现状**：克制的 thesis 文章路线（对，但缺记忆钩）。
- **更好**：一个可复述的三幕故事——
  「预测免费了（人人都见过删帖的大 V）→ 于是没人可信（共鸣）→
  所以我们给预测开收据（钩子：**"Pics or it didn't happen" for
  predictions / 预测圈的'无图无真相'**）」。
  加上 §3 的 founder receipts，叙事自带证据。
- **第一步**：story pack 30 秒版微调加入钩子句（P3 审后）。

## 6. 更强的 open-source / community 策略

- **现状**：代码顺手开源（被动）。
- **更好**：**标准先行**（O1）——receipt spec v0.1 公开 + 参考实现 +
  "自托管你自己的 ledger"教程。社区策略不是求 star，是让"收据格式"
  成为讨论预测可信度时的默认词汇。竞争者实现我们的 spec = 我们赢。
- **第一步**：30 天内 spec v0.1 上公开 repo（CX-6/FP-9 流程放行后）。

## 7. 更好的 research-to-product loop

- **现状**：研究线（quantum/spine）与产品线无环路，gate 单向防扩散（对）。
- **更好**：把唯一合法的研究主题定为**机制本身**——time-locked eval
  （O2）、抗 gaming 评分、resolution 自动化。这些研究每篇都直接
  强化产品，且都可发表。其它研究主题一律 gate 外拒绝。
- **第一步**：O2 position note 2 页（访谈周后，FP 排程）。

## 8. 更现实的 founder operating model

- **现状**：五轨并行 + 每日多任务（Phase 1 遗产，已被多次压缩仍偏重）。
- **更好**：**每天一个不可委派动作**原则——founder 每个工作日只欠
  项目一件事：1 个访谈 / 1 次接入推进 / 1 个发布按钮。其余全部
  是委派和验收。日清单从"3 重点"再砍到"1 必做 + 2 可选"。
- **第一步**：14 天队列照此重标（每行加粗唯一必做项——已在
  V2_ROADMAP 0–14 天节执行）。

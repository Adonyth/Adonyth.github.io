# MASTER_PLAN_V2_ROADMAP — 升级后路线图

> 唯一进度语言：证据阶梯（机制 L 级 / 访谈数 / non-owner 行数 /
> 付费信号）。每段含 not-to-do 与 kill criteria。
> 0–14 天与 NEXT_14_DAYS_MACRO_ACTION_QUEUE 完全一致（不另立队列），
> 此处只标注每天的**唯一必做项**（operating model §8）。

## 0–14 天（6/11–6/24）｜ 主题：第一次接触现实

- **Objective**：D1 pain 证实/证伪 + 第一个可分享 receipt URL +
  既有三死线执行（6/12 gate、6/13 golf、6/17 邮件）
- **每日唯一必做**（其余见 14 天队列）：CT-0 派发 → gate 冻结 →
  golf 签字 → 访谈消息 ×5 → 访谈 #1 → 检查点 → 邮件发出 →
  访谈 #2–3 → concierge 演练 → sample URL 上线 → 缓冲 → 复盘 →
  接入开始 → 14 天判定
- **Artifacts**：访谈纪要 ×5、receipt 示例 URL、UI_CURRENT_STATE、
  RETRO、PHASE4_REVIEW
- **Evidence 目标**：市场 L0→L1（pain 有访谈证据）
- **Not to do**：plan 再修订（证据棘轮）、新研究、P1+ UI、quantum 出 gate
- **Success**：≥4 访谈完成且 ≥2 确认 pain；URL 可分享
- **Kill/pivot**：5 访谈 0 pain → D2 plan B 启动（预案已备）

## 15–30 天（6/25–7/10）｜ 主题：第一个外部源

- **Objective**：1 个 non-owner 源 concierge 接入 ≥10 行 + spec v0.1 公开
  + founder receipts ×3 公开（BETTER §3）
- **Artifacts**：第一份外部源校准周报（FP-12）、spec repo、
  访谈 #6–10、（若 golf GO）golf rows 首批
- **Evidence 目标**：non-owner 0→≥10 行；O1 弱信号（外部 star/issue）
- **Not to do**：自动化 resolution 通用引擎、多源并行、融资 roadshow
- **Success**：外部源主动续第二周（不用催）
- **Kill**：concierge 三次邀约全拒且理由一致 → 该买家形态证伪，
  回访谈数据重选形态

## 31–90 天（7 月–9 月）｜ 主题：从收据到履历

- **Objective**：3 个 non-owner 源、≥100 行 resolved、1 个 design partner
  书面承诺、v1 立项判定（server-side 时间戳+表单+verifier 开源）
- **Artifacts**：v1 可用（若立项）、O2 position note、第一笔收入或
  付费意向书、（attorney 放行后）ledger 公开 + 60 天报告
- **Evidence 目标**：机制 L2→L3 候选（60 天 ledger 若续跑）；
  市场 L1→L2（有人用真实工作流接入）
- **Not to do**：团队扩张、SOC2 类重合规投入、第二 vertical
- **Success**：一个源的供给飞轮不需 founder 推也转一周
- **Kill**：90 天无任何付费信号且无自转供给 → 写 pivot/persevere memo，
  默认转 D2/O2 学术路线收缩运营

## 3–12 个月 ｜ 主题：标准与第二买家

- **Objective**：receipt spec 有 ≥1 个第三方实现或集成；time-locked
  eval 叙事进入 ≥1 个研究合作；agent 采购场景的可重复销售动作成形
- **Artifacts**：spec v1.0、研究 note 发表/预印、10+ 付费或 LOI 客户
  （量级假设，按 90 天数据修正）
- **Evidence 目标**：市场 L3（重复购买行为）；O4 监管假设查证完毕
- **Not to do**：自营预测、token 化、平台化（社区/评论/排行榜）
- **Success**：有人在我们不在场的对话里用"receipt"指代这类记录
- **Kill**：标准 12 个月零第三方兴趣 → O1 降回产品内部格式（不耻）

## 1–3 年 ｜ 主题：审计层成为默认

- **Objective**：N2 北极星的机构化——"agent 出货带 track record"在
  某个细分成为采购默认项；跨源履历图谱（moat 第四层）开始累积
- **Evidence**：客户把 Omytea 审计写进他们给客户的合同/marketing
- **Not to do**：仍然不做预测业务（宪法条款，永久）
- **Kill/转向**：若大平台原生内置同等机制且中立性被市场接受 →
  转标准维护者+数据信托角色（提前在 spec 治理里留此退路）

## 3–10 年 ｜ 主题：现实账本（N5，内部）

- 不写 KPI（GUARDRAILS §9：愿景句只当裁判用）。
- 方向性描述：当预测经济的参与者默认"重要断言应该有收据"时，
  谁维护那个最被信任的账本，谁就是这一层。我们从第一天起积累的
  全部纪律记录，就是竞争那个位置的资格证。

## 修订规则

本 roadmap 受 amendment §D 证据棘轮约束：30 天内仅 6/24 的
PHASE4_REVIEW 可触发修订（它会带来 ≥5 条访谈事实）。
